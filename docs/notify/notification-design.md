# 通知模块重构设计（sodex-watch + HYPE-watch）

> 状态：clarify 设计确认中（未生成 spec、未动代码）。
> 来源需求：`.claude/kit/spec/update-notification.md`。

## 一、核心目标

现状通知冗余（全币种展示 + 多条 banner + 平仓历史多条），阅读困难。目标：**只留本次变化、一眼看清哪个币做了什么动作**。

## 二、核心架构转变

`fetchAndReport` 从「一帧 → 一条消息（`classifyBanner` 取最高优先级动词）」改为「**按币种/动作拆，一帧可发 N 条独立消息**」。

- 遍历 `events`（仓位变化）→ 每个变化币各生成一条 OPEN/INCREASE/REDUCE 消息
- 平仓（CLOSE）→ 同帧所有平仓币**合并为一条**（列平掉的币 + 剩余全景 + 平仓历史）
- 遍历 `exitChanges`（离场单变化）→ 生成离场单消息（按动作细化 banner）
- 全空（纯 `closedIdsFp` 抖动）→ **不发**（消除现状的无意义 POSITION CHANGE）
- `START` / `SNAPSHOT` 例外：单条全景，行为完全不变

单动作帧仍是一条，不增噪；只有多动作帧才拆多条（本就该多条）。

## 三、消息类型全集

| 消息 | banner（中英同行） | 图标 | 仓位卡片 | 平仓历史 | ⭐️ |
|------|------|------|----------|----------|-----|
| 开仓 | OPEN POSITION 开仓 | 🟢 | 仅该币 | 无 | 仓位行前 ⭐️ |
| 加仓 | INCREASE POSITION 加仓 | 📈 | 仅该币 + 增加持仓行 + 保证金变化 | 无 | 增加持仓行 + 保证金行前 ⭐️ |
| 减仓 | REDUCE POSITION 减仓 | 📉 | 仅该币 + 减少持仓行 + 保证金变化 | 无 | 减少持仓行 + 保证金行前 ⭐️ |
| 平仓 | CLOSE POSITION 平仓 | 🔴 | 剩余全部仓位 / 无持仓 | 仅 1 条最新（去"最近N条"、⭐️） | 历史行前 ⭐️ |
| 离场单·设置 | ORDER PLACED 挂单设置 | 🏹 | 该币 + 挂单行 | 无 | 变化挂单行前 ⭐️ |
| 离场单·撤销 | ORDER CANCELED 挂单撤销 | 🏹 | 该币 + 挂单行 | 无 | 变化挂单行前 ⭐️ |
| 离场单·调整 | ORDER MODIFIED 挂单调整 | 🏹 | 该币 + 挂单行 | 无 | 变化挂单行前 ⭐️ |
| 离场单·混合 | OPEN ORDER 挂单变化 | 🏹 | 该币 + 挂单行 | 无 | 变化挂单行前 ⭐️ |
| 开始监控 | START WATCH 开始监控 | 👀 | 全币种（不变） | 最近 2 条（不变） | 无 |
| 每日镜像 | SNAPSHOT 每日快照 | 📸 | 全币种（不变） | 最近 2 条（不变） | 无 |

> ⭐️ 全站统一（原平仓历史的 `★` 也改 ⭐️）。

## 六、范围与约束

- 两端 `sodex-watch` / `HYPE-watch` 对称改（`render.mjs` + `watcher.mjs` 消息循环）
- `HYPE-copy` 不动（已核实无耦合；`this.positions` 仍全量获取，仅渲染过滤 → copy 依赖的 positions/copySignal 不受影响）
- `diffPositions` 量级（`5→8`）+ 保证金（HYPE `marginUsed` 直读 / sodex `size×entry/lev` 推算）数据现成，零新增请求
- 不碰 `emitCopySignal` / `recomputeStateFp` 触发逻辑
- 最后更新 `docs/update-log.md`

## 七、开放问题（已定）

1. **平仓多币合并的历史条数** → 每个平仓币各 1 条（不止 1 条），避免漏平仓信息；非平仓帧不显示历史。
2. **开仓消息不含"增加持仓/保证金变化"行** → 开仓是从 0 新建仓，无"变化前"值，直接显示持仓量。
3. **同帧「开 A + 平 B」** → A 允许同时出现在"开仓 A 消息"与"平仓消息剩余全景"，语义不同（动作 vs 平仓后快照），不去重。
4. **离场单消息显示完整仓位卡片 + 变化挂单行** → 给挂单一个仓位上下文。
