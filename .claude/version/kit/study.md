## [2026-05-31] v1.6 — 核心流程强制「全景图→速查表→管道图」三段式

### 变更

| 文件 | 说明 |
|------|------|
| `kit/study/templates/study-template.md` | 「核心流程」节内联三段骨架：① 横向全景图 ② ≤3 列速查表 ③ 纵向管道图，每段配串场文案，全 ASCII 不依赖 Mermaid |
| `commands/k/study.md` | Phase 6.6 第二步整理为 A/B/C 三节（A 核心流程三段式 HARD-GATE / B 值得学习 / C 借鉴建议）；核心流程判据为通用「流转图 + ≤3 列表 + 展开图」缺一未通过（不绑死符号，状态机/多路径可换样式）；Phase 6 维度行标「必出 ASCII 流程图」 |

### 动机

报告「核心流程」原为纯文字编号列表，链路/gate/回退/分支不直观。固化为「由表及里」三段缩放：全景图给流转骨架 → 速查表给命令静态属性（≤3 列防过宽）→ 管道图给逐命令子流程，各配短文案串场避免"图墙"。关键决策：**用内联骨架 + HARD-GATE 强制，而非引用 `docs/cli-output/describe-output-template.md`**——弱引用执行时易被跳过，内联进模板（AI 填充的产物）+ 命令侧字符校验才是强约束。

### 设计决策

- **三段粒度互补不重复**：全景=横向缩略只给顺序+gate；表=静态属性（职责/产物/约束）；管道=纵向展开子步骤/回退
- **速查表 ≤3 列**：5 列在 CLI 渲染过宽换行，砍掉「触发时机」（顺序交给全景图）、合并「产物+约束」
- **强制优先于 DRY**：三段骨架内联进模板，接受与 describe 库少量重复，换取"执行必出图"
- **纯 ASCII 不依赖 Mermaid**：终端/GitHub/编辑器通用，对齐既有分析文档风格
- **可校验**：HARD-GATE 以「三段图形/表格字符缺一」作为未通过判据；describe 库（A–J）作可选样式目录，状态机→顶层框、多路径→分路径

## [2026-05-31] v1.5 — 亮点机制提炼（与借鉴裁决解耦）

### 变更

| 文件 | 说明 |
|------|------|
| `commands/k/study.md` | Phase 6 新增 step 3「逐单元深挖实现细节」+ 维度表加「亮点机制提炼」行；新增 Phase 6.45「亮点机制提炼」独立阶段（不走零假设/反向验证，允许「无突出亮点机制」空结论）；Phase 6.6「完整文档」步骤内新增「值得学习的实现机制」节结构（与借鉴建议五问并列，避免重复渲染） |
| `kit/study/templates/study-template.md` | 「与 soso-kit 对比」前新增「## 值得学习的实现机制」章节骨架（四要素：机制名/解决什么问题/怎么实现/可迁移思想内核） |

### 动机

v1.4 之前 study 的全部分析压力都汇到「借鉴裁决」（是否适合 soso-kit）。但「是否适合搬进 soso-kit」与「设计思想是否值得学习」是正交问题：大量标志性机制不适合搬入单人 Claude 工具，却极值得理解其设计取舍。零假设借鉴闸（6.5）会把这类洞察作为「不借鉴」吞掉，导致 study 漏掉核心学习价值。

### 设计决策

- **两条问题线正交解耦**：6.45 只答「值不值得学习」（取证目标项目源码），6.5 只答「是否搬进 soso-kit」（取证 soso-kit 源码），互不污染
- **6.45 不走零假设/不定级**：禁止 ✓/✗/~ 与「soso-kit 已有/缺失」判断，避免借鉴倾向侵蚀学习提炼
- **亮点四要素 + 目标项目 file:line 取证**：机制名/解决什么问题/怎么实现/可迁移思想内核，找不到行号即删除防编造
- **示例抽象化**：评判维度（量化/分级、闸门、token 纪律、扩展解耦等）仅作启发，命令文本禁止点名任何具体外部项目
- **Phase 编号用 6.45 不重排**：保持既有跳转引用有效

## [2026-05-31] v1.4 — 分析质量四问元自检闸

### 变更

| 文件 | 说明 |
|------|------|
| `commands/k/study.md` | 新增 Phase 6.4「分析质量四问」强制元自检闸，卡在 Phase 6（草拟候选）与 Phase 6.5（逐候选裁决）之间；修正 Phase 6 维度表「四问」笔误（Phase 6.6 实为五问），补全对 6.4/6.6 的准确引用 |

### 动机

v1.3 的反向验证闸只对「单个候选」做裁决，无法拦截「分析整体」的两类病：① 没读到核心闭环就下判断（只读架构外壳/README/schema）；② 拿自画像/记忆取证而非源码；③ 凭「理念同构」武断下「零借鉴」结论。实测一次 OpenSpec 研究即触发：初版「零借鉴」因未读 archive 活规格闭环、且用自画像取证而被推翻，经补读源码后修正为「1 项边际借鉴 + 5 项跳过」。

### 设计决策

- **元自检 vs 逐候选裁决正交分层**：Phase 6.4 体检「分析本身」，Phase 6.5 裁决「每个候选」，两者都要做不可互相替代
- **四问精准对应根因**：信息充分性（防只读外壳）/ 依据是源码（防自画像取证）/ 反武断全否（防懒得挖）/ 深度到实现差异（防停在功能名）
- **「无可借鉴」须穷尽后得出**：第 3 问明确「合法结论但必须是穷尽细节后的结论，不是懒得挖的结论」，与 v1.3「禁止凑数硬留」形成双向防护
- **Phase 编号用 6.4 不重排**：保持既有跳转引用有效

## [2026-05-30] v1.3 — 反向验证闸 + 零假设借鉴

### 变更

| 文件 | 说明 |
|------|------|
| `commands/k/study.md` | Phase 6 拆为 6（草拟候选，禁止定级）/ 6.5（反向验证闸）/ 6.6（输出文档）；新增第 0 问零假设校验与源码证据硬约束 |
| `kit/study/templates/study-template.md` | 借鉴建议加「第 0 问零假设校验」+ 结论分级；对比表加「以源码为准」提示；删去与结论重复的「额外 token 消耗评估」空小节 |

### 动机

首轮借鉴判断只读自画像（抽象摘要）、不读 soso-kit 源码，把「自画像没提」误读成「soso-kit 没有」，导致给出伪需求型借鉴建议（防漂移门禁、eval 套件），需用户追问、回源码反证后才撤回。根因：流程缺「回 soso-kit 源码反证」这一步，且四问结构隐含「应该借鉴」的倾向。

### 设计决策

- **零假设 = 不借鉴**：每条建议默认不成立，只有 soso-kit 源码 `file:line`（证明缺失）或实测输出能推翻，对齐 constitution「证据落地」
- **Phase 6.5 反向验证闸**：三问筛查（是否已有等价物 / 是否真问题 / 核心提升 or 过度设计），凑数硬留被禁止
- **定级后移**：Phase 6 只草拟候选不定级，✓/~/✗ 一律在验证后定，避免先入为主
- **Phase 编号不顺延**：用 6.5/6.6 而非重排 7/8/9，保持既有跳转引用有效

## [2026-04-17] v1.1 — 借鉴建议四问强制化

### 变更

| 文件 | 说明 |
|------|------|
| `commands/k/study.md` | Phase 6 新增四问段落硬性要求：帮助大吗 / 有必要吗 / 提升哪些 / 结论 |
| `kit/study/templates/study-template.md` | 借鉴建议一节改为四问结构骨架 |

### 动机

首轮执行经常只给出"借鉴建议"列表和 token 评估，跳过"是否必要/是否有提升/最终结论"的显式作答，需要用户追问才补齐。将四问提升为硬性段落结构，避免再漏。

### 设计决策

- 四问**不可合并、不可省略**，即便项目价值极高或极低也必须逐项作答
- 裁决摘要（Phase 6 第一步）保留不变，四问作为详细分析里的强制段落
- 模板同步更新，保证 Write 时结构对齐

## [2026-04-12] v1.0 — 初始版本

### 新增

| 文件 | 说明 |
|------|------|
| `scripts/resolve-project.sh` | 三级项目解析：registry aliases → 本地目录 → GitHub clone |
| `scripts/update-project.sh` | 默认分支检测 + git pull（冲突时跳过继续） |
| `scripts/scan-project.sh` | 项目结构扫描：目录/入口/语言/commit/README + token 估算 |
| `scripts/generate-profile.sh` | soso-kit 自画像半自动生成（AUTO 区覆盖，MANUAL 区保留） |
| `scripts/save-study.sh` | registry 更新（aliases 合并）+ token 统计 |
| `registry.json` | 项目映射索引 |
| `soso-kit-profile.md` | soso-kit 自画像（对比基准） |
| `templates/study-template.md` | 研究文档模板 |
| `output/.gitkeep` | 文档输出目录 |

### 设计决策

- **脚本 + Workflow 混合**：机械操作脚本化节省 token，智能分析交给 Claude
- **registry.json (B方案)**：JSON 索引，程序化读写，低 token 消耗
- **自画像按需更新**：首次自动生成，后续用户确认是否更新
- **持久化需确认**：分析完成后询问用户，可拒绝
- **覆盖 + 变更记录**：重复 study 覆盖主体，追加变更记录
- **Token 估算**：字符数 / 3（与 context 系统一致）
