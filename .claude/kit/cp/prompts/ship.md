逐项审查本次改动，每条结论指向源码行号；无行号标 [推理] 并说明缺什么证据。

1. **是否真正解决了目标问题？** 先确认目的达成——没达成，后面几条无需展开，直接说明卡在哪。
2. **改动自身有没有问题？** bug / 逻辑错误 / 遗漏（边界、异常、未覆盖场景）/ 逻辑模糊 / 重复多余。
3. **是否引入对外副作用？** 回归、破坏既有行为、连带影响其他模块——区别于第 2 条的「自身缺陷」。
4. **有没有风险？** 收敛到：破坏性变更 / 数据与精度 / 安全与权限 / 影响范围是否可控。
5. **是否可以提交？** 给明确的「可 / 不可」结论；若不可，列出必须先解决的阻断项。

「听起来 / 通常 / 可能」是反模式。
