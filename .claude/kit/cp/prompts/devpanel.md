为我指定的 feature / 流程生成一个开发预览面板（dev panel），一键查看流程上各组件在不同状态 / 参数下的渲染。

## 适用判断
- 核心价值：给一个常驻入口，不走真实流程就能弹出任意弹窗 / 状态来看样式——**弹窗大小、数量都支持，小弹窗 / 单弹窗同样适用**（省去手动导航去触发）。
- 最划算：状态藏在异步 / 多步 / 需登录之后（手动走到很慢），或你要反复调样式。
- 唯一治不了的不是"数量少"，而是"某状态只能由 live 接口 / mutation 结果到达且无法静态 mock"（见下「分类处理」第三类）——这类按规则如实标出、不硬造，但不影响为其它状态正常生成面板。

## 状态枚举（关键：必须机械取全集，不许凭印象）
1. grep 目标 feature 下所有 `export function open*` 弹窗入口 → 贴命令 + 全部命中。若该项目弹窗用别的命名约定（如 `showXxx` / `createXxx` / 直接渲染的 `<XxxModal>`），换对应模式再 grep，确保不因约定不同而漏掉入口。
2. 对每个弹窗，grep / 读其状态分支的权威来源：scene / status 的 union 类型、enum、关键条件渲染（如 `status === 'success'`）→ 贴出找到的全集。
3. 把「弹窗 × 状态」清单列给我，标注可能漏的分支，等我确认后再生成。禁止从印象里编状态数。

## 分类处理（判定标准写死）
- 可直接打开：open*() 有参数能控制该状态 → action 直接 open*(参数)。
- 需包装：状态由 query / mutation 结果或内部步骤推进决定、open* 无参数可达 → 写 Dev 包装组件，复用真实布局 + 子组件，注入 mock 强制渲染。
- 依赖 live hook 无法静态 mock：被复用子组件调 useQuery / useMutation / useAuthState 等，DEV 下无真实数据会报错 / 空渲染 → 不要硬生成跑不起来的包装；把这类状态单列，说明「需额外 mock hook 或在真实流程里看」，交我决定。
