# 安全检查: Security

## 用户输入

```text
$ARGUMENTS
```

---

## 执行流程

### Step 0: 环境准备

```bash
# 获取 soso-kit 根目录
if [ -f ".claude/kit/cli/config.sh" ]; then
    KIT_ROOT="$(pwd)"
elif [ -f "../.claude/kit/cli/config.sh" ]; then
    KIT_ROOT="$(cd .. && pwd)"
elif [ -f "../../.claude/kit/cli/config.sh" ]; then
    KIT_ROOT="$(cd ../.. && pwd)"
else
    echo "❌ 未找到 soso-kit 配置"
    exit 1
fi
```

### Step 1: 解析输入

根据 `$ARGUMENTS` 的内容类型，提取需要检查的风险包信息：

**判断规则：**
- 包含 `http://` 或 `https://` → 链接输入
- 包含 `@` 或符合包名格式（如 `lodash<4.17.21`）→ 包名输入
- 其他 → 文本描述
- 无输入 → 仅使用内置恶意包列表扫描

**处理方式：**

**链接输入**：
1. 使用 WebFetch 工具抓取链接内容
2. 如果抓取失败 → 输出 `⚠️ 链接无法访问，请直接提供文本内容或包名`，停止等待用户重新输入
3. 抓取成功 → AI 从文章内容中提取涉及的包名和版本信息
4. 输出提取结果：`🔍 从文章中提取到以下风险包：[包名列表]`

**包名输入**：
1. 直接解析包名和版本条件
2. 输出：`🔍 检查目标：[包名@版本条件]`

**文本描述**：
1. AI 分析文本，提取涉及的包名和版本
2. 如果无法识别 → 提示用户明确提供包名和版本
3. 输出：`🔍 从描述中提取到以下风险包：[包名列表]`

**无输入**：
1. 输出：`🔍 无指定包名，将使用内置恶意包列表进行全量扫描`

---

### Step 2: 显示项目列表 + 选择

```bash
bash "$KIT_ROOT/.claude/kit/security/scripts/scan.sh" list
```

根据脚本输出，询问用户选择项目（全选 / 部分选择）。

等待用户回复后，记录选择结果（`all` 或编号列表如 `1,3,5`）。

---

### Step 3: 分支状态检测

```bash
bash "$KIT_ROOT/.claude/kit/security/scripts/scan.sh" branch-check "<用户选择>"
```

根据脚本输出：
- 有需要切换的项目 → 展示状态表格，询问用户是否确认切换
- 无需切换 → 直接进入 Step 4

等待用户确认：
- 确认 → 记录 `--confirm-switch`
- 拒绝 → 记录 `--skip-switch`

---

### Step 4: 扫描依赖

```bash
bash "$KIT_ROOT/.claude/kit/security/scripts/scan.sh" scan "<用户选择>" "<--confirm-switch|--skip-switch>"
```

脚本会输出每个项目的依赖列表（`DEPS:START` 到 `DEPS:END` 之间），以及状态信息（`STATUS:SCANNED` / `STATUS:SKIPPED:原因`）。

---

### Step 5: 风险比对

**AI 执行以下比对逻辑：**

1. **读取内置恶意包列表**：
   使用 Read 工具读取 `$KIT_ROOT/.claude/rules/malicious-npm-package.md`，提取所有恶意包名和版本。

2. **比对用户指定的风险包**（如 Step 1 有提取到）：
   - 精确匹配包名
   - 版本范围匹配（如 `lodash<4.17.21` 匹配所有低于该版本的 lodash）

3. **比对内置恶意包列表**：
   - 精确匹配包名和版本

4. **汇总结果**：
   - 按项目分组，记录每个项目的风险包和安全状态

---

### Step 5.5: 历史 lockfile 回溯（仅当 Step 1 提取到风险包时执行）

**目的**：回答"项目过去是否曾经引入过该风险包"。即使当前 lockfile 干净，曾装过一次就可能在 `pnpm install` 时触发过受污染包的 `postinstall`，意味着存在凭据外泄窗口期。

**执行**：将 Step 1 提取的风险包名（以及命名空间前缀，如 `@antv/`、`@lint-md/`）用 `|` 拼接，调用：

```bash
bash "$KIT_ROOT/.claude/kit/security/scripts/scan.sh" history-check "<用户选择>" "<pattern1>|<pattern2>|..."
```

脚本会在每个项目 `lockfile` 的完整 git 历史（所有分支）中搜索每个 pattern，输出 `HISTORY:START` 到 `HISTORY:END` 之间的命中数。

**判定规则**：
- `<pattern>: NONE` → 该项目从未引入过此风险包
- `<pattern>: N commits` → 该项目历史上曾出现过，标记为「⚠️ 历史命中」，建议核对凭据是否需要轮换

**何时跳过**：
- Step 1 无风险包（仅内置恶意包扫描）→ 跳过此步
- 项目非 git 仓库或无 lockfile → 脚本自动跳过

---

### Step 6: 输出报告

根据 Step 4 和 Step 5 的结果，输出结构化报告：

```
╔══════════════════════════════════════════╗
║        🔒 Security 安全检查报告          ║
╠══════════════════════════════════════════╣

📋 扫描概况：
  • 输入来源：[链接/包名/文本/内置列表] → 提取风险包：[包名列表]
  • 扫描项目：N/8（M 个跳过，K 个用户拒绝切换）
  • 同时比对：已知恶意包列表（26 个）
  • 历史回溯：[已执行 / 跳过（无风险包 pattern）]

⚠️ 风险项目（N 个）：
| 项目 | 风险包 | 当前版本 | 历史命中 | 风险原因 | 建议 |
|------|--------|---------|---------|---------|------|
| [项目名] | [包名] | [版本] | [N commits / NONE] | [原因] | [建议操作] |

✅ 安全项目（N 个）：
  [项目名列表]

⏭️ 跳过项目（N 个）：
| 项目 | 原因 |
|------|------|
| [项目名] | [跳过原因] |

╚══════════════════════════════════════════╝
```

**报告规则**：
- 风险项目为空时 → 显示 `✅ 所有扫描项目安全`
- 跳过项目为空时 → 省略跳过区块
- 建议列：恶意包 → "立即移除"；已知漏洞 → "升级至 [安全版本]+"
