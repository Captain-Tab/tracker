# Debug-On: 启动调试会话

## 用户输入

```text
$ARGUMENTS
```

---

## 元原则（强制）

debug 命令用**运行时数据**回答问题，不用 AI 推理。

- 插桩 1 行 ≈ 50 token，获取真实数据
- 读 200 行代码 ≈ 6000 token，仅产生推测
- 永远优先插桩，最小化静态分析

**输出原则**：
- 分析 / 推理 / 假设过程**全部静默**，不输出到用户
- 用户只需关心三件事：服务是否启动、插桩在哪里、是否可以复现

---

## 执行步骤

### Phase 0: 启动服务

```bash
KIT_ROOT="$(git rev-parse --show-toplevel 2>/dev/null || pwd)"
bash "$KIT_ROOT/.claude/kit/debug/scripts/start-server.sh" check
bash "$KIT_ROOT/.claude/kit/debug/scripts/start-server.sh" start "$PROJECT_ROOT"
```

操作（静默）：确认 node 可用、端口空闲、`.gitignore` 包含 `debug.log`、清理孤儿日志、启动服务。

**输出（仅此一行）**：
```
✅ Debug 服务: 端口 {PORT}
```

---

### Phase 1: 定位插桩点（全程静默）

**策略**：从数据流边界定位，不推断内部逻辑。

```
1. 从 bug 描述提取数据流向
   - 输入：触发操作是什么（用户行为、外部调用、定时任务）
   - 输出：期望结果是什么（返回值、状态变化、副作用）
   - 层次：数据经过哪些层（入口层 → 处理层 → 存储层 → 输出层）

2. grep 找层间交叉点（不读内部实现）
   - 入口层函数名（接收输入的函数）
   - 层与层之间的调用点
   - 输出层函数名（产生最终结果的函数）

3. 小范围 Read 确认边界位置
   - 目标：确认"这里能观测到变量 X"
   - 只读函数签名 + 入参/出参，不读内部逻辑
```

**关键规则 A — 异步/外部调用边界必须拆成"发出"和"返回"两点**：
当插桩边界是对外部系统的调用（钱包签名、HTTP、RPC、WebSocket、子进程、worker、IPC），
禁止只用"调用前 + 返回后"两点夹它。一旦调用挂起，"返回后"那点永不触发，而下面三种
情况日志完全一样、无法区分：
  (a) 请求根本没发出（卡在 wrapper 内部更早处）
  (b) 请求已发出、但没等到响应
  (c) 收到响应、卡在后续处理
必须在"我方把控制权交给外部系统的那一刻"补一点——下沉到 wrapper 内部、紧贴实际发出动作
（如 `provider.request` / `.send` / `signTypedData` 调用点），或 hook 该发出方法记录"已发出"。
判据：任何 `await 外部调用()`，至少要有「调用前 / 已发出 / 已返回」三点，而非两点。
为定位发出点而读 wrapper 内部，是边界探测的一部分，**不算违背本 Phase「不读内部逻辑」的禁令**。
例外（发出点不可编辑）：若我方最后一行可控代码即是该外部调用本身（发出点在 node_modules
等不可插桩依赖内），则"调用前"即视为"已发出"点，三点合法地塌缩为两点；可观测边界到此为止。

**关键规则 B — 别让起始假设缩小插桩范围**：
按"输入 → 最终外部效果"的完整数据流布点，覆盖整条路径，而非只插当前假设涉及的那几处。
起始假设经常是错的；某段被当黑盒跳过，等数据推翻假设时才发现没插，会多耗昂贵的复现轮次。

> 全程不输出分析过程，定位完成后直接进入 Phase 2。

---

### Phase 2: 插桩（集合模式）

**策略**：一次性插完所有边界点，不分批。用户复现是瓶颈，减少复现轮次比减少插桩数量更重要。

**插桩模板**（`{PORT}` 替换为 Phase 0 实际端口）：

```typescript
fetch('http://localhost:{PORT}/log',{method:'POST',headers:{'Content-Type':'application/json'},body:JSON.stringify({tag:'[DEBUG:P1]',data:{variableName},timestamp:Date.now()})}).catch(()=>{}); // [DEBUG:P1]
```

> `tag` 格式：`[DEBUG:P{序号}]`，序号跨轮次递增（P1、P2… 不重置）。

**安全放置规则**：插桩必须在可执行路径上，不能放在纯函数体内、模块顶层初始化、同步渲染路径等副作用受限位置。如需观测这类位置的值，用该语言对应的副作用包装（如 JS 的 `useEffect`、异步回调等）。

**输出（仅此格式）**：
```
✅ 已插桩 N 个点：
- path/to/file.ts:42 — [DEBUG:P1] {观测变量}
- path/to/file.ts:67 — [DEBUG:P2] {观测变量}
```

---

### Phase 3: 收集

写入轮次标记：
```bash
ITER=$(grep -c '\[ITER_START\]' "$PROJECT_ROOT/debug.log" 2>/dev/null || echo 0)
ITER=$((ITER + 1))
TS=$(($(date +%s) * 1000))
curl -s -X POST "http://localhost:{PORT}/log" -H 'Content-Type: application/json' \
  -d "{\"tag\":\"[ITER_START]\",\"data\":{\"iteration\":$ITER},\"timestamp\":$TS}"
```

**输出（仅此）**：
```
▶ 第 {ITER} 轮收集中（端口 {PORT}）
复现 bug 后回复 "done"
```

等待用户 "done"。收到后直接进入 Phase 4，不停止服务。

---

### Phase 4: 分析（静默推理）

精确读取本轮数据：
```bash
LATEST=$(grep -n '\[ITER_START\]' "$PROJECT_ROOT/debug.log" | tail -1 | cut -d: -f1)
# Read 工具：file_path=debug.log offset=$LATEST
```

内部分析：按 `sessionStart` 分组 → 逐假设验证 → 定位根因。

**输出（仅结论）**：

已定位根因：
```
## 第 {ITER} 轮

根因: [一句话描述]
修复: path/to/file.ts:line — [具体改动]
```

未定位：
```
## 第 {ITER} 轮

路径未命中 / 数据不足，追加插桩：
- path/to/file.ts:89 — [DEBUG:P{N+1}] {观测变量}

▶ 第 {ITER+1} 轮 — 再次复现，完成后回复 "done"
```

**迭代约束（强制）**：
- ❌ 禁止重读已读过的文件
- ❌ 禁止回到 Phase 1 重新静态分析
- ✅ 仅追加插桩点（在已有 Px 序号上递增）
- ✅ 插桩点未触发 → 换位置，不重读代码

> 以上禁令针对"还没定位、别盲目静态分析"的状态。

**Off-ramp（数据出现下列可观测信号时的唯一例外）**：当本轮数据出现——
「预期的下游步骤从未被执行」（边界 probe 已证明，如 connect 从未被调用）或
「第三方只回了无 cause 的不透明错误码」——说明失败在你调用第三方之前/边界，
**停止追加插桩**（再深插也观测不到），转为验证【调用方输入是否满足被调方契约】：

> **off-ramp 前置条件（强制）**：「下游步骤从未执行」只有在你已插了"出站发出点"探针
> （见 Phase 1 规则 A）、确认请求**确实已交给第三方**之后，才足以 off-ramp。若你只在
> 外部调用"前/后"夹了点，下游探针缺失既可能是"没发出"也可能是"发出没响应"——此时
> **不可 off-ramp**，必须先把探针下沉到发出点（我方边界、可观测）区分清楚。
> 不要用"第三方内部看不到"来跳过"我方是否已发出"这个可观测边界。
> **逃生口**：若发出点本身在不可编辑依赖内（见规则 A 例外），"调用前"即是我方可观测边界的
> 终点，下游缺失探针 = 已发出无响应，off-ramp 合法——不要因无法再下沉而无限追加插桩。
- ① 读被调方的类型/文档/源码契约（单项目也有；此时读它不算违背上面禁令）
- ② 单变量实验：一次只改一个入参，复用 Phase 3 收集循环看成败翻转；实验性改动
     **不是 `[DEBUG:]` 探针、`debug-off` 清不掉**，观测完必须立即还原
- ③ 有 working 参考系时，diff 两边调用参数（最快，但非必需）

> "是不是传参/配置错"是读契约后得出的**结论**，不作为本 off-ramp 的触发条件（防过早 off-ramp）。

定位到根因后回到下方"已定位"输出格式。

---

```
✅ 根因已定位，修复完成。运行 /k:debug-off 清理插桩和日志。
```
