## 示例 1: 默认模式 - startup 目录（推荐）⚡

### 准备工作

```bash
# 1. 将 PRD 文档放到 startup 目录
cp ~/docs/user-auth-prd.md .claude/kit/startup/

# 2. 确认文件存在
ls .claude/kit/startup/
# 输出: user-auth-prd.md
```

### 执行转换

**用户输入**:
```
"使用 document-to-spec"
```

**AI 执行流程**:

1. **检测文件来源**
   ```
   检查 .claude/kit/startup 目录
   找到: user-auth-prd.md
   ```

2. **解析文档**
   ```bash
   python scripts/parse-document.py .claude/kit/startup/user-auth-prd.md --format json
   ```

3. **分析需求**
   - 提取用户故事
   - 分类功能需求
   - 推导边界情况

4. **生成英文文件名**
   ```
   PRD 标题: "用户认证系统 PRD"
   提取关键词: ["用户", "认证", "系统"]
   翻译为英文: ["user", "authentication", "system"]
   生成文件名: user-authentication.md
   ```

5. **生成 spec**
   ```
   写入: .claude/kit/spec/user-authentication.md
   ```

**输出结果**:
```
✅ Spec 文档生成完成！

📄 文件位置: .claude/kit/spec/user-authentication.md
📋 内容摘要: [详细内容...]
```

## 示例 2: 转换 Markdown PRD（指定路径）

### 输入文件: `user-auth-prd.md`

```markdown
# 用户认证系统 PRD

## 背景

当前系统缺少用户认证功能，无法区分不同用户，导致数据安全风险。

## 目标

为系统提供安全可靠的用户认证功能，支持邮箱登录和第三方登录。

## 用户故事

### US-001: 邮箱登录 [P0]

As a registered user
I want to login with email and password
So that I can access my account

**验收标准**:
- 输入正确凭据后 2 秒内完成登录
- 错误密码时显示明确提示
- 连续 5 次失败后锁定 15 分钟

### US-002: 邮箱注册 [P0]

As a new user
I want to register with email
So that I can create an account

### US-003: 密码重置 [P1]

As a user who forgot password
I want to reset my password
So that I can regain access

## 功能需求

### 核心功能
- FR-001: 邮箱密码登录
- FR-002: 邮箱注册
- FR-003: 密码加密存储（BCrypt）

### 重要功能
- FR-004: 密码重置
- FR-005: 登录日志记录

### 增强功能
- FR-006: Google OAuth 登录
- FR-007: 双因素认证

## 成功指标

| 指标 | 目标值 |
|------|--------|
| 注册完成时间 | < 2 分钟 |
| 登录成功率 | > 98% |
| 接口响应时间 | P95 < 500ms |
```

## 用户故事

### US1: 邮箱登录 (P1) 🎯 MVP

**场景**: 作为已注册用户，我想要使用邮箱和密码登录，以便访问我的账户

**验收**:
- [ ] 当输入正确凭据时，2 秒内完成登录并跳转首页
- [ ] 当输入错误密码时，显示"密码错误"提示

### US2: 邮箱注册 (P1) 🎯 MVP

**场景**: 作为新用户，我想要使用邮箱注册账户，以便使用系统功能

**验收**:
- [ ] 当输入有效邮箱和密码时，创建账户并发送验证邮件
- [ ] 当使用已注册邮箱时，显示"邮箱已存在"提示
- [ ] 当密码强度不足时，显示密码要求（至少 8 位，含数字和字母）

### US3: 密码重置 (P2)

**场景**: 作为忘记密码的用户，我想要重置密码，以便重新访问账户

**验收**:
- [ ] 当输入注册邮箱时，收到重置密码链接
- [ ] 当点击链接时，跳转到密码重置页面（链接 24 小时有效）
- [ ] 当设置新密码后，可以使用新密码登录

- [ ] 当邮箱验证链接过期时，如何处理？
- [ ] 当并发登录同一账户时，Session 如何管理？
- [ ] 当密码包含特殊字符时，是否正确处理？

- FR-002: 用户可以使用邮箱注册新账户

- FR-004: 系统必须在 2 秒内响应登录请求

**应该 (SHOULD)**:
- FR-005: 用户可以重置忘记的密码
- FR-006: 系统应该记录所有登录尝试日志
- FR-007: 连续 5 次登录失败后锁定账户 15 分钟

**可选 (MAY)**:

## 示例 5: 批量处理多个 PRD

### 场景: 10 个功能需要转换

```bash
#!/bin/bash
# batch-convert.sh

PRD_DIR="~/docs/prds"
SPEC_DIR=".claude/kit/spec"

for prd in "$PRD_DIR"/*.md; do
    echo "处理: $prd"
    python scripts/parse-document.py "$prd" --format json > /tmp/parsed.json
    
    # 调用 AI 处理（在对话中）
    echo "请基于 /tmp/parsed.json 生成 spec"
    
    # 等待用户确认
    read -p "继续下一个？(y/n) " -n 1 -r
    echo
    if [[ ! $REPLY =~ ^[Yy]$ ]]; then
        break
    fi
done
```

**注意**: 
- 批量处理需要人工确认每个结果
- 避免完全自动化，确保质量

## 常见问题

### Q1: 生成的 spec 不完整怎么办？

**A**: 分步处理
1. 先查看解析结果: `--format text`
2. 检查是否缺少关键章节
3. 如果 PRD 本身不完整，手动补充
4. 重新运行转换

---

### Q2: 文字模式和文件模式有什么区别？

**A**: 适用场景不同

**文字模式**:
- ✅ 快速启动，无需准备文件
- ✅ Token 使用极少（约 500-1000）
- ⚠️ 需要人工补充细节
- **适用**: 简单需求、快速原型

**文件模式**:
- ✅ 信息完整，提取准确
- ✅ 适合复杂需求
- ⚠️ 需要解析时间
- ⚠️ Token 使用较多（2000-3000）
- **适用**: 正式 PRD、复杂功能

**选择建议**:
```
需求复杂度 < 3 个用户故事 → 文字模式
需求复杂度 ≥ 3 个用户故事 → 文件模式
```

---

### Q3: 如何处理中英文混合的 PRD？

**A**: 脚本自动处理
- 中文 token 效率更高（1 token ≈ 1.5 字符）
- 英文稍低（1 token ≈ 4 字符）
- 混合文档自动适配

---

### Q4: PDF 解析失败怎么办？

**A**: 转换格式
```bash
# 方法 1: 使用在线工具转换为 Markdown
# https://pdf2md.com

# 方法 2: 使用 Pandoc
pandoc prd.pdf -o prd.md

# 方法 3: 手动复制内容到 Markdown
```

---

### Q5: 成功指标为什么不能写技术指标？

**A**: Spec 阶段关注业务目标，不是技术实现

**错误示例** ❌:
```markdown
| 指标 | 目标值 |
| 响应时间 | < 500ms |
| 并发能力 | 1000 QPS |
| 点击率 | > 5% |
```

**正确示例** ✅:
```markdown
| 指标 | 目标值 |
| 用户体验 | 用户能够顺利完成操作 |
| 功能可用性 | 核心功能正常可用 |
| 安全保障 | 用户数据安全保护 |
```

**原因**:
1. Spec 定义"做什么"，Plan 定义"怎么做"
2. 技术指标会限制设计空间
3. 业务目标更稳定，技术指标易变

---

### Q6: 如何自定义优先级关键词？

**A**: 修改脚本
```python
# 编辑 scripts/parse-document.py

priority_keywords = [
    '问题', '目标', '需求',  # 保留默认
    '核心指标', '关键路径'   # 添加自定义
]
```

5. **补充边界情况和指标**

### ❌ Don't

1. **不要直接处理超大 PDF**（先优化）
2. **不要完全依赖自动化**（需要人工确认）
